## 📤 Создание бекапа (отправка изменений)

### Быстрый способ:

```powershell
cd E:\FuraEdet_Diploma
git add .
git commit -m "Backup: описание изменений"
git push
```

### Пошагово:

1. **Добавить все изменения:**
   ```powershell
   git add .
   ```

2. **Создать коммит с описанием:**
   ```powershell
   git commit -m "Backup: добавил регистрацию пользователей"
   ```
   
   Примеры сообщений:
   - `"Backup: настроил Django проект"`
   - `"Backup: добавил API авторизации"`
   - `"Backup: создал HTML страницы"`
   - `"Backup: исправил ошибки в моделях"`

3. **Отправить на GitHub:**
   ```powershell
   git push
   ```

---

## 📋 Рекомендации для бекапов

### Когда делать бекап:
- ✅ После завершения каждого этапа (промпта)
- ✅ После исправления ошибок
- ✅ В конце рабочего дня
- ✅ Перед большими изменениями

### Хорошие сообщения коммитов:
- `"Backup: Промпт 1 - настройка Django"`
- `"Backup: Промпт 2 - модель User"`
- `"Backup: Промпт 3 - API регистрации"`
- `"Backup: исправление ошибок в авторизации"`
- `"Backup: добавлена валидация форм"`

### Плохие сообщения (избегайте):
- ❌ `"Backup"`
- ❌ `"Изменения"`
- ❌ `"asdf"`
- ❌ `"123"`

## 🔍 Проверка статуса

### Посмотреть, что изменилось:
```powershell
git status
```

### Посмотреть историю коммитов:
```powershell
git log --oneline
```

### Посмотреть изменения в файлах:
```powershell
git diff
```

---

## 📥 Восстановление из бекапа

### Посмотреть все коммиты:
```powershell
git log --oneline
```

### Вернуться к конкретному коммиту:
```powershell
git checkout <hash_коммита>
```

### Вернуться к последнему коммиту:
```powershell
git checkout main
```

---

## ⚠️ Важно

1. **Регулярно делайте бекапы** - не теряйте работу!
2. **Пишите понятные сообщения** - потом будет легче найти нужный бекап
3. **Проверяйте перед push** - убедитесь, что всё работает
4. **Не коммитьте секреты** - пароли, API ключи должны быть в .env
